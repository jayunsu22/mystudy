## 4. 콘텐츠 입력 (채팅 → Airtable)

사용자가 채팅에서 URL이나 텍스트를 주면, Claude가:
1. 내용을 읽고 8~15개 정도의 복습 카드(질문/모범답안/힌트)로 정리
2. `학습자료` 테이블에 자료 레코드 1개 생성 (제목은 사용자가 부르는 이름 그대로, 예: "면세점영어")
3. `카드` 테이블에 카드들을 생성, `자료` 링크 필드로 위 레코드와 연결, `단계`='신규', `이지팩터`=2.5,
   `간격일수`=0, `다음복습일`=오늘, `복습횟수`=0, `최근결과`='미학습', `활성`=true

파일 업로드/폴더 감시 방식은 채택하지 않음 — "간편하게 채팅으로 하는 게 낫겠다"는 사용자 결정(2026-08-22).

## 5. 세션 구조

앱을 열 때 "신규학습" / "복습" 중 사용자가 직접 선택(시간 기준 자동판단 안 함, 2026-08-22 결정).
왕복 통근 약 1시간 가정: 출근길엔 신규학습, 퇴근길엔 복습.

### 5.1 신규학습 — 그라데이션 리콜 (Pimsleur 방식)

세션당 신규 카드 최대 5~8개(`CONFIG.MAX_NEW_PER_SESSION`). 각 카드는 즉시(첫 소개) → 1분 후 → 5분 후 →
15분 후, 총 4번 연속 정답이면 "졸업"하여 그날 저녁부터 복습 대상(SM-2)으로 전환된다. 오답이면 그 단계에서
30초 후 재시도(단계는 유지, 진급하지 않음). 여러 카드를 인터리빙하며 진행 — `srs-utils.js`의
`pickNextAction`이 스케줄러 역할. 세션이 끝나기 전에 못 끝낸 카드는 다음 신규학습 세션에서 처음부터
다시 시작한다(단순화를 위한 설계 — 서버에는 졸업한 카드만 기록되고 세션 중간 진행 상태는 저장하지 않음).

참고: [Pimsleur의 graduated interval recall](https://www.pimsleur.com/blog/why-graduated-interval-recall-is-the-key-to-mastering-a-new-language/)

### 5.2 복습 — SM-2

카드마다 `이지팩터`(기본 2.5, 최소 1.3)를 관리. 정답 시 이지팩터가 소폭 상승하고 `간격일수 × 이지팩터`로
다음 간격이 늘어남(처음 복습이면 무조건 1일). 오답(랩스) 시 간격을 1일로 리셋하고 **다음복습일을 오늘로
설정** — 실제 대화에서 못 알아들을 정도의 발음/이해 문제를 오래 방치하지 않기 위한 결정(2026-08-22,
"실제로 영어로 대화할 때 상대방이 못 알아들으면 안 된다"는 우려 반영).

졸업 직후 카드는 `다음복습일`=오늘로 설정되므로, 그날 저녁 복습 세션에 "오늘 새로 배운 것"과 "예전부터
있던 것"이 자연스럽게 섞여서 나온다(사용자 요청: "반복학습은 오늘꺼랑 예전꺼랑 섞어서"). 서버(n8n)가
목록을 무작위로 섞어서 내려준다.

참고: [Anki SM-2 알고리즘 설명](https://help.remnote.com/en/articles/6026144-the-anki-sm-2-spaced-repetition-algorithm)

### 5.3 발음 피드백의 한계

브라우저 음성인식(Web Speech API)은 오디오 파형이 아니라 이미 텍스트로 변환된 결과만 준다. 그래서
실제 발음/억양을 직접 분석할 수는 없다. 대신 "음성인식 결과가 모범답안과 다르게 들렸다"는 것 자체를
발음 문제의 근거로 삼아, Gemini가 `pronunciation_tip`(발음 팁)을 함께 준다 — 완벽한 음성 분석은
아니지만, 실제로 남이 못 알아들을 만큼 다르게 들린 경우를 잡아내는 데는 의미 있는 근사치다.

## 8. N8N 백엔드 (웹훅)

기존 레일웨이 인스턴스에 워크플로우 1개(`n8n_workflow.json`), 웹훅 노드 7개.

| 웹훅 | 메서드 | 용도 |
|---|---|---|
| `/repeat-study-new-get` | GET | 신규(단계=신규, 활성) 카드 전체 반환 |
| `/repeat-study-review-get` | GET | 오늘 복습 대상(단계=복습, 다음복습일≤오늘) 카드를 섞어서 반환 |
| `/repeat-study-grade` | POST | Gemini로 채점 + (복습 단계면) SM-2 스케줄 갱신 + 복습기록 로그 |
| `/repeat-study-graduate` | POST | 신규 카드를 복습 단계로 전환 (다음복습일=오늘) |
| `/repeat-study-materials-get` | GET | 자료별 카드수/총복습횟수/최근학습일 집계 |
| `/repeat-study-card-update` | POST | 화면모드에서 카드 내용 수정 또는 삭제 |
| `/repeat-study-cards-get` | GET | 화면모드용 전체 카드 원본 (단계/활성 무관) |

인증 없음(개인용). 프론트 fetch는 레퍼런스와 동일하게 25초 타임아웃 래퍼 + 실패 시 토스트 에러 메시지.

## 9. 프론트엔드

레퍼런스와 동일 구성: 프레임워크 없는 순수 HTML/CSS/JS.

- `index.html` + `app.js` + `style.css` — 음성 학습(신규학습/복습 모드 선택), `srs-utils.js`(공용 SRS
  스케줄러)를 함께 로드.
- `admin.html` + `admin.js` + `admin_style.css` — 자료별 통계 확인 + 카드 내용 수정/삭제.
- `srs-utils.js` — Pimsleur 그라데이션 리콜 스케줄러, 날짜 포맷, 채점 요청 payload 빌더. `tests/srs-utils.test.js`로 테스트.
- 캐시버스팅: `?v=YYYYMMDD`, 해당 JS/CSS 수정 후 push할 때마다 갱신.

## 10. 배포 (GitHub)

- 새 저장소 `mystudy`를 사용자가 github.com에서 빈 저장소로 직접 생성. push 자체도 이 세션에는 GitHub
  인증 수단이 없어(gh CLI 미인증) 사용자 PC 터미널에서 직접 실행.
- GitHub Pages를 저장소 루트에서 서빙 → `https://<계정>.github.io/mystudy/`.
- 이후 수정 시에도 항상 push 전 사용자 확인 후 Claude가 직접 push.

## 11. 향후 확장 여지 (지금 범위 아님)

- 신규학습 세션 중간에 앱을 닫으면 진행 상태가 저장되지 않고 다음 세션에 처음부터 다시 시작 — 필요해지면
  세션 상태를 Airtable이나 localStorage에 저장하는 방식 추가 가능.
- 발음 피드백은 STT 인식 결과 기반 근사치 — 필요해지면 실제 오디오를 분석하는 별도 발음평가 API 연동 고려.
